## Purpose

Implement pure immutable domain values for a future read-only Resolve snapshot adapter and
feature-specific readiness assessment without making any Resolve API calls.

## Required domain

Names may be refined without changing semantics:

- IdentityScope:
  - PERSISTENT_VERIFIED
  - SESSION_LOCAL_VERIFIED
  - SNAPSHOT_LOCAL
  - UNKNOWN
- CapabilityState:
  - SUPPORTED
  - UNSUPPORTED
  - UNKNOWN
- CaptureConsistency:
  - CONSISTENT
  - UNSTABLE
  - UNVERIFIED
- SnapshotCompleteness:
  - COMPLETE_FOR_DECLARED_CAPABILITIES
  - PARTIAL
- AdapterProvenance
- CapabilityManifest
- NativeTrackSnapshot
- NativePlacementSnapshot
- NativeTimelineSnapshot
- FeatureRequirementProfile
- ReadinessStatus / ReadinessReason
- pure feature-readiness evaluation

## Mandatory semantics

1. Identity scope is categorical lifetime evidence, never a confidence/probability.
2. Capability support is separate from observed field value.
3. UNSUPPORTED/UNKNOWN capability must never synthesize FALSE/default values.
4. UNVERIFIED capture consistency must never become CONSISTENT implicitly.
5. Snapshot completeness != feature readiness.
6. Readiness evaluates an explicit requirement profile.
7. Snapshot READY is not Apply/Safety/Authority permission.
8. filename, track name/index, duration or similar heuristics may not create persistent identity.
9. media identity and placement identity are separate.
10. UNKNOWN retime is not IDENTITY_1X.
11. state_token is optional only when freshness/state capability is honestly unavailable/unknown; do
    not fabricate a meaningless token.
12. snapshot values are immutable and deterministic.
13. no Resolve mutation or API calls.
14. no ADR-021 mapping inference from FPS/duration.
15. no relationship execution semantics.

## Suggested readiness profiles

At minimum define one conservative analysis profile suitable for future Pause analysis.

A destructive-apply profile may be represented only as requirements metadata; it must not imply edit
authorization.

## Required tests

At minimum prove:

- immutable snapshot/domain values
- defensive copy
- identity lifetime enum distinctions
- SESSION_LOCAL_VERIFIED != SNAPSHOT_LOCAL
- capability SUPPORTED with observed UNKNOWN is valid
- capability UNSUPPORTED cannot masquerade as observed FALSE
- capture CONSISTENT/UNSTABLE/UNVERIFIED remain distinct
- UNVERIFIED does not satisfy requirements that demand verified capture consistency
- PARTIAL != feature READY
- COMPLETE_FOR_DECLARED_CAPABILITIES does not automatically satisfy a richer feature profile
- missing state token cannot satisfy a requirement that demands freshness proof
- arbitrary/random placeholder state token is not generated by the foundation
- repeated-media placements remain distinct
- track name/index do not create semantic role/identity
- filename-only media identity is never required/accepted as authoritative identity
- UNKNOWN retime is preserved
- snapshot provenance retained
- no TASK-010 mapper/classifier/authority/safety/executor side effects
- TASK-001..010 regression remains green

## Explicitly out of scope

No Resolve API/scripting integration, native object discovery, state-token derivation, timeline
mutation, identity heuristics, semantic track-role inference, ChangeSet/partial refresh, media
intelligence, EditPlan lowering, Safety execution, DB/network/UI.
